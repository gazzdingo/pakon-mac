Design mockups · Pakon F-135 Plus for macOS

The scanner is a darkroom instrument.
The software should behave like one.

Static HTML mockups for the replacement of the vendor's 2002 PSI application — grounded in what was actually extracted from PSI.exe, TLXClientDemo.exe, PTS.exe and the shipped manual (see docs/51-vendor-gui.md), and in what this repo's driver and colour pipeline can really do today. Same capabilities, different century.

Design plan

Extends the direction already accepted in docs/50-ui-milestone-0-plan.md (palette, hairline layout, density-trace signature). Equal-RGB neutrals only; one accent, reserved.

Filament never paints ordinary buttons. If gold is on screen, the machine is doing something — lamp warming, transport feeding, a frame rendering, a reference going stale.

  • Type — three voices. Chrome and controls: AVENIR NEXT / SEGOE UI with letterspaced uppercase labels. Roll names and film stocks: Iowan Old Style / Palatino — the ledger voice, because rolls are things you write on boxes. Every changing number: SF Mono / IBM Plex Mono with tabular figures. System stacks because mockups are self-contained (no font CDNs); the build can ship licensed faces per docs/50.
  • Layout — one shell for every mode: 44 px top bar (brand · modes · film readout · state chips), session rail left, image stage on Void in the centre, one inspector right, and the filmstrip with its density trace across the bottom. 4 px grid, radius 0, no shadows; depth is hairlines on Plate.
  • Dark only, deliberately — the surround a print is judged against must contribute no hue and no glare; a light theme would be a different room, not a different skin. This is a committed choice, not an omission (docs/50 §B1).
  • Motion — one curve (cubic-bezier(.55,.05,.2,1)), three uses: strip advance, trace draw, state pulse on Filament dots. All behind prefers-reduced-motion.

What we kept from the vendor

Vendor behaviourWhere it went
Continuous strip, frames found afterwards Scan shows a strip building, never a per-frame "flatbed preview"; Review exposes the boundary lane over the real strip — the machine's actual model, made visible. (docs/47 §6)
Scan-ahead with two independent status lanes Scan and Export are separate modes with separate progress; exporting never blocks scanning. (PSI dual progress bars, dialog 128)
Ctrl-Shift-S — rescan with same settings, no dialog "Scan again, same settings" toggle (⇧⌘S); settings persist per session. (How_to_Scan.htm)
Corrections always visible beside every frame Per-frame offsets shown in Review's inspector and on thumbnail markers; footers state offsets numerically. (per-thumb badge stack, image9.jpg)
Keyboard colour grammar (E/R/T/A + S/F/D, c/v) R/G/B/D channel select, −/+/0, C/V copy-paste — same philosophy, saner keys. (Color.htm)
Roll-level scene balance first, per-frame offsets second The auto column in every parameter row; offsets never replace auto. (docs/11 §5 — per-frame-only balancing breaks the look)
Film LED contract — machine prompts for film Transport prompts in Scan's stage header and status line; never "pull the film". (LED legend, How_to_Scan.htm)
Accept/Reject that excludes from export but keeps the frame Reject in Review; struck-through, skipped rows in the Export queue. (Picture_Menu.htm)
Warnings that don't abort (emulsion side, tail-first) Boundary-confidence and film-handling notes are amber annotations, not modals. (strings 36/37/39)
"Save As Raw" escape hatch Export → Colour → "Linear, scanner profile embedded". (Save_As.htm)
Calibration as named, per-purpose tests with progress Dark/flat/lamp as separate cards with per-step status and history. (Calibration_Wizard.htm; PSI dialogs 1008–1026)
About box = full hardware manifest Diagnostics rail: every board, firmware, serial — one "Copy manifest" button. (PSI dialog 100)

What we dropped, and why

Vendor behaviourWhy it's gone
Orders, products, packages, IQueue, CDs, kiosks Lab economics. The unit of work here is the roll; the only product is files.
EasyOrder giant-button wizard It deskilled minilab clerks. Its real lesson — good defaults, few decisions — survives as DX auto-detection and "scan again, same settings".
Modal editing dialogs; fixed 3-column thumbnail-only review The image is the interface: one large preview, inspector at the side, edits render in place without blocking the app.
CMY printer-channel vocabulary Kept the R/G/B/density semantics (they map to the pipeline), renamed to photographer terms with D-units for exposure.
8-bit-only export The pipeline is 16-bit planar end-to-end; 16-bit TIFF is the default export, not an engineering backdoor.
A pile of intermediate files per decode Owner's rule: one image per frame, parameters not products. Renders are cache; only Export writes files; the workspace is temporary and cleaned on quit — with the sole real tension (unexported edits vs delete-on-close) handled explicitly in housekeeping.html.
Hidden technician settings ("do not change unless directed") Replaced by a read-only Diagnostics mode with real telemetry. Nothing is secret; writes stay locked.
2002 visual style (MFC chrome, royal-blue panels, bevelled bitmaps) Reproduced the capabilities, not the look. Dark neutral ground, hairlines, one reserved accent.

Honesty notes

  • Frame "photographs" in these mockups are gradient placeholders — the owner's captures are private and no real image ships in a mockup.
  • All device numbers are real values from this unit and repo (11.6 MiB/s sustained, 57 900 lines / 0 losses, dark means 1120.5 · 1443.0 · 1160.9, LED on-counts 492/239/104, AFE 13/13/13 · −18/−26/−20, FPGA 0x0061) — except the temperatures in °C, which are illustrative: the sensor scale is only partly decoded (docs/38–39), and the panel says so.
  • Serial 16275 is the registry-recovered serial; reading it from the physical unit is still an open task (docs/42-port §gaps).
  • The keyboard map and boundary-editing interactions are proposals; everything else mirrors capabilities the tools already have or the vendor demonstrably shipped.
